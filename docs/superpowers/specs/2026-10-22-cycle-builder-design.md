# Конструктор цикла тренировок — спецификация

- Дата: 2026-10-22
- Статус: на ревью
- Исходная схема: `/home/UCBerkeley/Downloads/cycle8.xlsm`
- Рабочая папка: `/home/UCBerkeley/cycle-builder`

## 1. Назначение

Локальное веб-приложение, которое позволяет удобно рассчитывать и редактировать программу тренировок по схеме `cycle8.xlsm`, не работая с Excel-макросами и формулами напрямую.

Приложение должно:
1. Загружать полный цикл из `cycle8.xlsm` как готовый шаблон.
2. Позволять менять упражнения, 1ПМ, структуру цикла, подходы/повторы/проценты, прогрессию и коэффициенты метрик.
3. Мгновенно пересчитывать рабочие веса и метрики.
4. Печатать программу, сохранять PDF и выгружать Excel.
5. Сохранять проект в браузере и поддерживать резервную копию JSON.

### Критерии успеха

- Пользователь вводит 1ПМ и получает готовую программу без ручных формул.
- Любое изменение процента, повторов, подходов или 1ПМ сразу отражается на весе и итогах.
- Расчёт шаблона совпадает с `cycle8.xlsm` для всех 216 строк упражнений.
- Программа пригодна для печати и передачи тренеру в Excel.
- Приложение работает офлайн после первой загрузки.

## 2. Границы версии 1

### Входит

- Один проект / один атлет в браузере.
- Шаблон `cycle8`: 12 недель × 3 дня × 6 упражнений, 18 уникальных упражнений.
- Редактирование справочника упражнений: название, 1ПМ, коэффициент воздействия `D`, множитель `E`, шаг округления.
- Редактирование структуры: количество недель, количество и названия дней, состав упражнений в дне, порядок упражнений.
- Редактирование схем: подходы, повторы, процент от 1ПМ; добавление/удаление групп.
- Прогрессия 1ПМ: сложный процент, линейная, без прогрессии; разгрузочные недели.
- Округление веса: автоматическое как в xlsm или фиксированный шаг.
- Метрики: тоннаж, КПШ, средний вес, относительная интенсивность, интенсивность по Фунтикову, время.
- Редактирование таблицы коэффициентов Фунтикова и порогов времени.
- Печать/PDF, экспорт Excel, JSON-бэкап.
- Автосохранение в `localStorage`.

### Не входит

- Аккаунты, облачная синхронизация, несколько устройств.
- Учёт выполненных тренировок, история, графики прогресса атлета.
- Расчёт 1ПМ по весу тела или другим формулам.
- Фунты и другие единицы измерения.
- Календарные даты тренировок и планировщик.
- Мобильное приложение и PWA-обёртка.
- Импорт произвольных xlsm-файлов.

## 3. Анализ исходной схемы

`cycle8.xlsm` содержит листы `F`, `Цикл`, `Упражнение`, `Справка`.

- `Цикл` — основная программа: 12 микроциклов по 37 строк.
- Каждый микроцикл содержит 3 тренировочных дня: `Пн`, `Ср`, `Пт`.
- В каждом дне 6 упражнений. Всего 18 упражнений, по 6 на каждую мышечную группу:
  - Пн: жим стоя, подъём гантели перед собой, подъём гантелей в стороны, присед, присед на груди, разгибания ног;
  - Ср: жим лёжа, жим на наклонной, кроссовер, французский жим, трицепс на блоке, разгибания из-за головы;
  - Пт: тяга на прямых ногах, наклоны, тяга гантели в наклоне, тяга верхнего блока, бицепс стоя, молотковые сгибания.
- В строке упражнения до 4 групп подходов. Для каждой группы заданы вес, повторы, подходы и процент.
- Вес вычисляется из 1ПМ строки и процента, затем округляется.
- 1ПМ каждого упражнения увеличивается на 1% за микроцикл (сложный процент).
- Скрытые строки `Чт`/`Пт` в каждом микроцикле не содержат упражнений и не участвуют в расчёте.
- Лист `F` содержит таблицу коэффициентов для интенсивности по Фунтикову: 100 значений, соответствующих 1–100% 1ПМ.
- Лист `Справка` содержит описание показателей и требования к атлету; в расчётах не участвует.
- VBA-макросы служат для очистки, скрытия строк и вывода одного упражнения; генерации программы в них нет.

## 4. Пользовательские сценарии

1. **Быстрый старт.** Открыть приложение → загружается шаблон `cycle8` → ввести свои 1ПМ в разделе «Упражнения» → получить пересчитанную программу → распечатать или выгрузить Excel.
2. **Корректировка упражнения.** Изменить 1ПМ или шаг округления → все веса и метрики пересчитываются.
3. **Изменение схемы.** В неделе 3 заменить `10×3 @ 60%` на `8×4 @ 65%` → вес и итоги дня/недели обновляются.
4. **Изменение структуры.** Добавить четвёртый день или убрать упражнение из всех недель → структура обновляется, пустые недели/дни помечаются предупреждением.
5. **Прогрессия.** Задать шаг 2% и отметить неделю 6 разгрузочной → 1ПМ пересчитываются по выбранному правилу.
6. **Генератор волны.** Выбрать упражнение и недели 1–8, задать старт 50% и шаг 5% → проценты заполняются автоматически, повторы и подходы сохраняются.
7. **Печать.** Выбрать «Весь цикл» → предпросмотр → печать или сохранение в PDF.
8. **Передача тренеру.** Выгрузить Excel с листами «Сводка» и «Неделя 1…12».
9. **Резервная копия.** Выгрузить JSON → очистить браузер → импортировать JSON → проект восстановлен.

## 5. Модель данных

Все данные проекта сериализуемы в JSON. Идентификаторы — строки UUID; в шаблоне используются стабильные slug-идентификаторы.

```ts
type Unit = 'kg';
type RoundingMode = 'auto' | number;

interface Exercise {
  id: string;
  name: string;
  oneRM: number | null;      // кг
  impact: number;            // D, коэффициент воздействия на организм
  multiplier: number;        // E, множитель (гантели/блок)
  rounding: RoundingMode;    // 'auto' или шаг в кг
  note?: string;
}

interface DayTemplate {
  id: string;
  name: string;              // Пн, Ср, Пт или произвольное
}

interface SetGroup {
  id: string;
  percent: number;           // 0..100
  reps: number;              // целое > 0
  sets: number;              // целое > 0
}

interface Entry {
  id: string;
  exerciseId: string;
  groups: SetGroup[];
}

interface WeekDay {
  dayTemplateId: string;
  entries: Entry[];          // пустой массив = отдых
}

interface Week {
  id: string;
  label: string;             // "Неделя 1"
  isDeload: boolean;
  days: WeekDay[];
}

interface ProgressionConfig {
  mode: 'compound' | 'linear' | 'none';
  stepPercent: number;       // например, 1 = +1%
  deload: {
    mode: 'hold' | 'reduce';
    reductionPercent: number; // 0..100
  };
}

interface TimeThreshold {
  belowPercent: number;      // процент, ниже которого действует factor
  factor: number;
}

interface MetricsConfig {
  funtikovTable: number[];   // длина 101, индексы 0..100
  timeThresholds: TimeThreshold[];
  timeFallbackFactor: number;
  impactHeavyThreshold: number;  // 0.8
  impactLightThreshold: number;  // 0.4
  impactHeavyFactor: number;     // 6
  impactMediumFactor: number;    // 3
  impactLightFactor: number;     // 1.5
}

interface Project {
  schemaVersion: 1;
  id: string;
  name: string;
  createdAt: string;         // ISO 8601
  updatedAt: string;         // ISO 8601
  unit: 'kg';
  defaultRounding: RoundingMode; // шаг для новых упражнений
  exercises: Exercise[];
  dayTemplates: DayTemplate[];
  weeks: Week[];
  progression: ProgressionConfig;
  metrics: MetricsConfig;
}
```

### Решения по модели

- Порядок дней и недель определяется порядком элементов в массивах.
- Названия и порядок дней общие для цикла (`dayTemplates`).
- Состав упражнений и схемы задаются отдельно в каждой неделе (`WeekDay.entries`). Это позволяет менять одну неделю, не затрагивая остальные.
- `WeekDay.entries = []` означает день отдыха.
- `percent` хранится числом 0–100, а не долей 0–1.
- `rounding: 'auto'` означает правило xlsm; число — фиксированный шаг в кг.
- `defaultRounding` применяется к новым упражнениям; у каждого упражнения можно задать свой шаг, который имеет приоритет.
- Метрики не хранятся в проекте: они всегда вычисляются из данных.

## 6. Расчёт

### 6.1. 1ПМ недели

Для упражнения с базовым 1ПМ `base` и недели `w` (нумерация с 1):

```text
trend(w) =
  base,                                      если mode = 'none'
  base * (1 + step/100)^(w-1),               если mode = 'compound'
  base * (1 + step/100 * (w-1)),             если mode = 'linear'
```

Разгрузочная неделя не меняет дальнейший тренд:

```text
prevTrend(w) = trend(w-1), для w = 1 prevTrend = base

effectiveOneRM(w) =
  trend(w),                                  если неделя не разгрузочная
  prevTrend(w),                              если isDeload и deload.mode = 'hold'
  prevTrend(w) * (1 - reduction/100),        если isDeload и deload.mode = 'reduce'
```

Следующая обычная неделя продолжает считаться от `trend`, а не от уменьшенного значения разгрузки.

Ограничения: `stepPercent >= 0`; `0 <= reductionPercent <= 100`.

### 6.2. Вес

```text
step = rounding === 'auto'
  ? (oneRM_week > 50 ? 2.5 : oneRM_week < 15 ? 0.1 : 1)
  : rounding

weight = percent === 0 ? 0 : mround(oneRM_week * percent / 100, step)
```

`mround` повторяет Excel `MROUND`:

- округление к ближайшему кратному шага;
- половина округляется от нуля;
- для положительных значений: `floor(value / step + 0.5)` с защитой от floating point;
- результат приводится к 6 знакам после запятой.

Если `oneRM` не задан (`null`), вес равен `null`, а weight-зависимые метрики не рассчитываются.

### 6.3. Метрики одной группы

```text
tonnage          = weight * reps * sets * E
kpsh             = reps * sets
funtikov         = weight * reps * sets * f(percent) * E * D
timeMinutes      = sets * t(percent) * dFactor(D)
```

`f(percent)` — коэффициент из таблицы Фунтикова.

Пороговая логика `f` повторяет xlsm:

```text
percent < 30            -> 0
30 <= percent < 35      -> table[33]
35 <= percent < 40      -> table[38]
40 <= percent < 45      -> table[43]
45 <= percent < 50      -> table[48]
percent = 50            -> table[50]
50 < percent < 100      -> table[floor(percent)]
percent >= 100          -> table[100]
```

Для нецелых процентов выше 50 используется нижняя граница. Это осознанное исправление: исходная формула Excel при `50.5%` не находит совпадения и возвращает 0.

`t(percent)`:

```text
percent < 45 -> 0.5
percent < 55 -> 0.8
percent < 65 -> 0.9
percent < 75 -> 1.0
percent < 85 -> 1.1
иначе        -> 1.2
```

`dFactor(D)`:

```text
D >= 0.8 -> 6
D <= 0.4 -> 1.5
иначе    -> 3
```

Пороги и факторы времени, а также границы `D` редактируются в настройках. Значения по умолчанию соответствуют xlsm.

### 6.4. Агрегация

- Упражнение: сумма по группам.
- День: сумма по упражнениям.
- Время дня: если сумма времени упражнений равна 0, то 0; иначе `floor(сумма + 30)` минут. Добавка 30 минут соответствует xlsm (разминка/подготовка).
- Неделя: сумма тоннажа, КПШ, времени и Фунтикова по дням.
- Цикл: сумма по неделям.
- Средний вес: `тоннаж / КПШ`.
- Относительная интенсивность упражнения: `средний вес / (1ПМ_недели * E)`.

Если у упражнения не задан 1ПМ:

- вес и weight-зависимые метрики показываются как `—`;
- КПШ и время всё равно считаются;
- упражнение исключается из тоннажа, среднего веса, относительной интенсивности и Фунтикова;
- в интерфейсе и итогах отображается предупреждение.

Если `percent = 0`, вес равен 0, тоннаж и Фунтиков равны 0, КПШ и время считаются.

## 7. Валидация

Типы проблем: `error` и `warning`. Ошибки блокируют экспорт; предупреждения не блокируют.

### Ошибки

- Нет ни одной недели.
- Нет ни одного шаблона дня.
- Неделя содержит день с неизвестным `dayTemplateId`.
- В неделе повторяется `dayTemplateId`.
- `oneRM <= 0`, если значение задано.
- `impact <= 0` или `multiplier <= 0`.
- `percent < 0` или `percent > 100`.
- `reps` или `sets` не целые, меньше 1.
- `stepPercent < 0`.
- `reductionPercent < 0` или `> 100`.
- `funtikovTable` имеет длину не 101 или содержит не числа.
- `timeThresholds` не возрастают по `belowPercent` или содержат не числа.
- `entry.exerciseId` ссылается на несуществующее упражнение.
- Импортируемый JSON не соответствует схеме.

### Предупреждения

- У упражнения не задан 1ПМ, но оно используется.
- Упражнение не используется ни в одной неделе.
- В дне нет упражнений.
- В неделе нет ни одного упражнения.
- Дубли названий упражнений (без учёта регистра и пробелов).
- Одно упражнение встречается в дне дважды.
- `stepPercent > 10`.
- Больше 52 недель, больше 7 дней, больше 20 упражнений в дне или больше 12 групп в упражнении.

## 8. Интерфейс

### Общие принципы

- Русский язык, единицы — кг.
- Светлая нейтральная тема, тёмный текст, один акцентный цвет.
- Десктоп-ориентированный интерфейс; корректная работа до ширины 768 px.
- Слева — навигация, сверху — название проекта, статус автосохранения и кнопки «Печать»/«Excel».
- Все числа редактируются в полях с немедленным пересчётом.
- Опасные действия требуют подтверждения.
- Пустые состояния содержат пояснение и кнопку действия.
- Ошибки и предупреждения видны рядом с элементом и на «Обзоре».

### Страницы

#### Обзор

- Карточки: количество недель, тренировок, упражнений, суммарный тоннаж, КПШ, время.
- График тоннажа по неделям (столбцы).
- Список недель с тоннажем, КПШ и временем; переход к неделе.
- Блок предупреждений и ошибок.
- Кнопки «Сбросить к шаблону cycle8», «Печать», «Excel».

#### Программа

- Горизонтальная лента недель, добавление/дублирование/удаление недели.
- Карточки дней выбранной недели.
- Строка упражнения:
  - название и 1ПМ недели;
  - группы в виде компактных блоков `подходы × повторы @ % → вес`;
  - итоги строки: тоннаж, КПШ, время.
- Редактирование группы в поповере: подходы, повторы, процент; вес пересчитывается сразу.
- Добавление/удаление групп и упражнений.
- Перестановка упражнений и дней.
- Дублирование дня и недели.
- Переключатель «Редактировать структуру»: добавление дня, переименование, удаление; добавление упражнения в текущую неделю или во все недели.
- Генератор волны: выбор упражнений и недель, стартовый процент, шаг, режим (`линейно`, `волна`, `постоянно`).

#### Упражнения

- Таблица: название, 1ПМ, `D`, `E`, округление, количество использований.
- Поиск по названию.
- Inline-редактирование.
- Добавление и удаление упражнения; при удалении показывается, из скольких строк оно будет удалено.
- Подсказка по `D` и `E`.

#### Настройки

- Название проекта.
- Прогрессия: режим, шаг, параметры разгрузки.
- Округление по умолчанию для новых упражнений; у существующих шаг можно переопределить в таблице упражнений.
- Метрики: таблица Фунтикова (101 строка, сворачиваемая), пороги времени, факторы `D`.
- JSON: экспорт и импорт.
- Сброс к шаблону `cycle8`.

#### Экспорт

- Область: весь цикл / выбранная неделя / выбранный день.
- Формат: печать/PDF или Excel.
- Предпросмотр печатной версии.
- Кнопки «Печать» и «Скачать Excel».

### Печать

- A4, портрет, поля 12 мм.
- Одна неделя на страницу; при выборе дня — один день на страницу.
- Шапка: название проекта, номер недели, пустое поле для заметок.
- Таблицы по дням: упражнение, подходы, повторы, %, вес; подытоги дня.
- Итоги недели: тоннаж, КПШ, время.
- Интерфейс, навигация и кнопки скрыты.
- Цвета переводятся в чёрно-белый вид, чтобы не тратить тонер.

## 9. Экспорт Excel

Используется библиотека SheetJS (`xlsx`).

- Лист «Сводка»: неделя, тоннаж, КПШ, время (мин), средний вес, Фунтиков.
- Листы «Неделя 1»…«Неделя N»:
  - шапка с названием проекта и недели;
  - колонки: день, упражнение, подходы, повторы, %, вес, тоннаж, КПШ, время;
  - по одной строке на группу подхода;
  - объединённая ячейка дня;
  - строка итогов дня;
  - строка итогов недели.
- Форматы: вес `0.0`, процент `0"%"`, тоннаж `0`, время `0`.
- Ширины колонок и закреплённая шапка.
- Имя файла: `cycle-builder-YYYY-MM-DD.xlsx`.
- При наличии ошибок экспорт блокируется.

## 10. JSON-бэкап

- Экспорт: полный объект `Project` в файл `cycle-builder-backup-YYYY-MM-DD.json`.
- Импорт:
  1. прочитать файл;
  2. проверить JSON и `schemaVersion`;
  3. проверить структуру и ссылочную целостность;
  4. показать сводку: название, недели, упражнения;
  5. после подтверждения заменить текущий проект и сохранить.
- Неизвестная более новая версия схемы отклоняется с понятным сообщением.
- Версия 1 не поддерживает миграции; поле `schemaVersion` нужно для будущих версий.

## 13. Шаблон cycle8

- `src/data/cycle8.seed.json` генерируется скриптом `scripts/extract-cycle8.py` из исходного xlsm и коммитится в репозиторий.
- Приложение не читает xlsm во время работы.
- В шаблоне:
  - 18 упражнений с исходными 1ПМ, `D`, `E`, `rounding: 'auto'`;
  - 3 шаблона дней `Пн`, `Ср`, `Пт`;
  - 12 недель, в каждой 3 дня по 6 упражнений;
  - группы подходов с процентами, повторами и подходами из xlsm;
  - прогрессия `compound`, шаг `1`, разгрузок нет;
  - коэффициенты Фунтикова и пороги времени по умолчанию.
- Неделя 1 шаблона должна совпадать с эталонными значениями из раздела 3.
- Скрипт также формирует `tests/fixtures/cycle8.expected.json` с рассчитанными весами и метриками для всех строк.

## 14. Тестирование

### Модульные тесты

- `mround`: положительные, отрицательные, половина шага, floating point.
- `autoStep`: границы 15 и 50.
- `trend` и `effectiveOneRM`: compound, linear, none, hold, reduce, разгрузка на первой неделе.
- `funtikovCoefficient`: 29.9, 30, 34.9, 35, 39.9, 40, 44.9, 45, 49.9, 50, 50.5, 99, 99.9, 100.
- `timeFactor`: 44.9, 45, 54.9, 55, 64.9, 65, 74.9, 75, 84.9, 85.
- `dFactor`: 0.4, 0.5, 0.8.
- Расчёт строки `Жим стоя`, неделя 1.
- Агрегация дня: добавка 30 минут и округление вниз.
- Валидация: каждая ошибка и предупреждение.
- JSON round-trip.

### Эталонный тест шаблона

- Загрузить `cycle8.seed.json`, рассчитать цикл.
- Сравнить с `cycle8.expected.json`:
  - веса — точное совпадение;
  - тоннаж, КПШ, Фунтиков, время — допуск `0.01`.
- Проверить итоги недели 1: `39304`, `818`, `17762.032`, `278` минут.

### Проверка сборки

- `npm run test`
- `npm run build`
- `npm run dev` — ручная проверка сценариев из раздела 4.

### Критерии приёмки

1. Приложение запускается командой `npm run dev`.
2. Шаблон загружается: 12 недель, 3 дня, 18 упражнений.
3. Строка `Жим стоя` недели 1 даёт веса `32.5`, `42.5`, `50`; тоннаж `2040`; КПШ `48`; время `23.4`; Фунтиков `972.7`.
4. Неделя 1 даёт тоннаж `39304`, КПШ `818`, время `278` минут, Фунтиков `17762.032`.
5. Изменение 1ПМ или процента мгновенно меняет вес и итоги.
6. Добавление/удаление недели, дня, упражнения и группы работает и не ломает расчёт.
7. Пустой 1ПМ даёт предупреждение и `—`, приложение не падает.
8. Печать показывает недели без интерфейса.
9. Excel-файл содержит «Сводку» и листы всех недель.
10. JSON-экспорт и импорт восстанавливают проект без потерь.
11. `npm run test` и `npm run build` проходят.

## 15. Риски и решения

| Риск | Решение |
|---|---|
| Расхождение с xlsm из-за округления | Эталонный тест по всем 216 строкам, `mround` с защитой от floating point |
| Потеря данных при очистке браузера | JSON-бэкап и подсказка на странице экспорта |
| Сложность интерфейса из-за полной свободы | Разделение на «Программу» и «Настройки», массовые действия с явным выбором области |
| Случайное удаление упражнения из всех недель | Подтверждение с количеством затронутых строк |
| Некорректный JSON | Строгая валидация и отказ от импорта с сообщением |
| Печать не помещается на A4 | Компактная таблица, одна неделя на страницу, проверка предпросмотра |
